# 2026-11-27: architecture review and safe refactors

An unattended run reviewed the structure of the code after the MVP sprint and the 2026-11-26 audit, wrote it down in [docs/architecture.md](../architecture.md), and did the refactors with the best value for their risk, each in its own layer of a `gh stack`. **Nothing a homeowner sees changed:**
- no golden changed on any layer (`git diff` of `testdata/` from #6 to #15 is empty);
- every layer's binary produced byte-identical output to the stack base on about 10,000 outputs from the full county database. That comparison ran before `main` (with #7) was merged into #6. The rebase onto it had no conflicts, and after it the goldens and `scripts/check.sh` on every layer were the proof;
- `live-eval -n 200 -seed 1` at the stack top and at `main` both found 200 of 200 live reports identical to the database (outputs at the end).

## Where the stack sits

The brief said to stack on the test run's top branch. The test run left no marker and no `headless/2026-11-27-tests*` branch, locally or on GitHub, and `docs/dev/2026-11-27-tests.md` exists nowhere. The test run hadn't produced anything beyond #6 when this run started.

The existing `gh stack` held one layer, #6 (the audit fixes). So this stack goes on #6, not on `main`:

`main` ← #6 audit fixes ← #8 docs ← #9 format ← #10 window ← #12 rules ← #13 packet ← #14 eval ← #15 live

Basing on `main` would have conflicted with #6 in exactly the files refactored here (`packet.go`, `web/report.go`, `cli/format.go`). `gh stack merge` merges #6 and this stack together.

**#7 (e2e and fuzz tests) merged into `main` while this stack was open.** `main` was then merged into #6, which had one conflict (a line of `testdata/README.md`; `main`'s wording, which counts the cases right, was kept), and the layers above were rebased onto it with no conflicts. #7's overlaps had been prepared for:
- **`internal/e2e`:** the import rule (#8) lists it, and the architecture page now names it.
- **`search.FormatPIN`:** #7's fuzz test calls it, and #9 had replaced it with `format.PIN`. It's kept as a one-line wrapper (a fix commit on #9).
- **`-n` checks in `runSample` and `runLiveEval`:** #14 leaves both functions in place, so #7's lines carried through unchanged. That's why `eval.go` and `runLiveEval` are 3 lines longer than when this report was first drafted.
- **The `check` and `report` usage lines:** #6 and #7 made the same change, which merged cleanly.

## How the review ran

Seven independent reviewers each covered one dimension: the dependency graph, the domain model, presentation duplication, data access, long functions, configuration, and extensibility walk-throughs. Two adversarial verifiers then re-read every finding in the code and tried to refute it. All 69 findings held. About a quarter needed corrections (a count, a line number, a missing site), and the corrections are used below. Before acting on a finding I checked the code myself.

## Findings

### Dependency graph

After this stack (before: the same graph without `format`):

```
L5 entry      cmd/assessgap ─► cli                tools/fixture ─► ingest, store;  tools/tune ─► comps, store
L4 command    cli ─► bor comps format ingest live packet refresh search store web
L3 site       web ─► bor comps format packet search web/views
L2 render     packet ─► bor comps format          web/views ─► bor
L2 pipeline   live ─► comps ingest socrata store  refresh ─► ingest
L1 storage    ingest ─► socrata store             store ─► socrata
L0 leaves     bor  comps  format  socrata  search(─► format)
test-only     fixture ─► ingest store;  golden, e2e: none
```

- **Clean before this run, and still clean:** no cycles, no upward edges, only `cli` imports `web`, and presentation never imports the data side. Before, `packet`, `web` and `cli` each held their own copies of the formatting helpers.
- **Nothing enforced the graph.** `cmd/assessgap/imports_test.go` now does (#8).
- **Hidden coupling the graph doesn't show:**
  - `web` runs raw SQL on `cook.db` in five places (`server.go`, `search.go`, `township.go`) and on `app.db` in one. That is the signup insert, which a notifier would need too.
  - `cli/backtest.go` and `tools/tune/cache.go` each carry their own appeal SQL. `tune`'s comment says it "mirrors" the backtest, but the strings differ.

### Domain model

- **The core types are where they should be:** `comps/types.go` (`Home`, `Comp`, `Stats`, `Report`, `NbhdStat`, `Sale`) and `bor` (`Group`, `State`, `Status`).
- **The view structs in `web/views` are projections, not duplicates.** Their field names and Go types are golden keys (the web goldens marshal them with no JSON tags), so they can't be merged or retyped without regenerating goldens.
- **Stringly typed values:**
  - the AV stage (`"certified"` compared in 4 places, with the "certified, else mailed" choice written in SQL 4 times);
  - the verdict (`"weak"`/`"strong"`/`"possible"` typed as literals in `report.templ`);
  - the window state (now `bor.State.Slug()`, #10);
  - class codes (`"299"` in three packages).
- **Named types for PIN and money: not done, and recommended against for now.**
  - A `type PIN string` would touch almost every package for little gain. The real problem was the duplicated formatter, now `format.PIN`.
  - Money stays `float64`: the JSON output must not change, and the AVs are whole dollars from the county.
  - A typed AV stage (`comps.Stage`) is cheap and encodes identically, but the web's `Mailed bool` is a golden key. It's proposal A2.
- **Township names** reach `bor.StatusOf` raw from `parcel.township_name` on the report path, but are made canonical first on the search and township pages. `StatusOf` matches case-insensitively, and the 38 names match today, so nothing is wrong yet. Signups store the raw name for a PIN signup and the canonical name for a township-page signup (proposal A4).

### Presentation duplication

- **7 helpers were copied byte for byte across the CLI, the web page and the PDF:** money, num, perSF, pct, baths, titleCase and the PIN format. 4 more differed only in their placeholder for an unknown value: miles, year, land, dash. The CLI, web and PDF copies are now `internal/format` (#9).
- **The filing window's pieces were copied too:** the state names twice, "N days left / last day" three times, and the long date layout three times. They're now shared (#10). Each surface keeps its own sentences.
- **Kept apart on purpose:** `comps/analyze.go`'s `money` (`int64(x+0.5)`) and its thousands separators (truncating) differ from the others on negative, half-cent or fractional inputs. They stay in `comps` (proposal A1).

### Data access

- **The report code's data contract is the `build.sql` schema through `*sql.DB`, not a Go interface.** Live mode builds an in-memory SQLite database with the same `store.LoadRaw` and `ingest.Build`, then runs the same `comps.Engine`. `TestLiveMatchesDatabase` and `live-eval` prove the two are interchangeable for reports.
- **A Go data-source interface would add a layer without removing any code, so there isn't one.** `docs/architecture.md` now states the seam.
- **Hand-synced lists:**
  - `build.sql`'s positional `INSERT … SELECT` (CREATE and SELECT must keep the same column order);
  - `comps/load.go`'s `homeColumns` against `scanHome` (23 positional items);
  - the served-table list, which lives only in `ops/deploy/sync-data.sh` (twice, with an index count);
  - `ingest.Columns`, which is already shared well (live mode, the fixture tool and the synthetic tests all read it).

### Long functions and files

`evalBacktest` (122 lines), `evalSample` (103), `live.Fetch` (95), `store.LoadRaw` (86) and `packet.summary` (80) were the long functions in `internal/`. `packet.go` (648), `eval.go` (582) and `live.go` (404) were the long files. See the size tables below.

### Configuration

- **Engine thresholds were already one block in `comps/analyze.go`**, but the surfaces retyped the floor of 3 (8 literals) and the "states a reduction" condition (3 copies). Both are now `comps.Stats` methods (#12), except the backtest's frozen buckets.
- **The quoted rates (92/84/67/52/25%)** were typed in `analyze.go`, `pages.templ` and `methodology.md` with nothing tying them together. `comps/rates_test.go` now does (#12).
- **`bor` already holds the session's facts in one place**, and the templates use its constants by name. The count "38 townships" is typed in templates; `nav_test` covers it.
- **Database paths:** `db build`, `db validate` and `db finalize` ignore `$ASSESSGAP_DB`, while the other commands honor it (question 2).
- **`SOCRATA_APP_TOKEN`** is read two ways: `os.Getenv` in `ingest` and `env.Getenv` in `cli/live.go`. The page size of 50,000 is typed twice. Web limits and timeouts are spread over `web/server.go`, `web/limit.go` and `cli/serve.go`, with `Retry-After` literals repeating the durations.

## Proposals left for the maintainer

These need a judgment call about behavior or golden keys, or were too large for this run.

**A. They change what someone sees, or a golden key**
1. **A1. One money format in `comps` too.**
   - `comps`' reasons text rounds money with `int64(x+0.5)` and truncates thousands (`humanize.Comma(int64(x))`). That differs from `format.Money` and `format.Num` for negative or fractional values.
   - The inputs are whole-dollar AVs today, so the outputs likely agree. A fractional land area (`LandSF`) or an even-count median square footage in the flags would differ, though.
   - Switching means a golden diff to review, or proof that none occurs.
2. **A2. A typed AV stage** (`comps.Stage`, with `Mailed`, `Certified` and later `BoardFinal`), plus one SQL helper for the "certified, else mailed" choice now written in `comps/load.go`, `refresh/refresh.go` and `live/queries.go`. JSON is unchanged. Replacing the web's `Mailed bool` with the stage changes 8 web golden files' keys.
3. **A3. A typed verdict** (`comps.Tier`), used by the templates instead of the literals `"weak"`, `"possible"` and `"strong"`. Same golden-key caveat for `views.ReportData.Verdict`.
4. **A4. Canonical township names everywhere:** `bor.LookupTownship` before `StatusOf` on the report path, and in the signup row. The output is identical while all 38 spellings match. It's a fix if the county ever changes one.
5. **A5. `search.ClassKind` from `comps.InScope`** (audit P4, F22). About 4,460 unsupported class-2 parcels are labeled "Home" in search results.
6. **A6. `sample`'s output order.** It prints two maps in Go's random order and depends on today's date, so it can't be compared run to run. Sorting the keys changes its output.

**B. Structure, behavior-neutral but larger**
1. **B1.** `views.HomeRow` embeds `comps.Features` instead of copying its fields. Golden keys are unchanged (embedded fields are promoted), and it saves 2 files per new characteristic.
2. **B2.** A small signup package (store, list by township, mark sent) used by `web` and a future notifier. Township slug and path helpers move from `web/township.go` to `bor`, since email links need them. Settle W6 (double opt-in) first.
3. **B3.** The served-table list in Go (`ingest.ServedTables`) with a `db slim` step, replacing the list in `sync-data.sh` (fits audit P3). Then a scheduler entry chains `refresh.sh` and `sync-data.sh`.
4. **B4.** A page registry in `web`: path, title, sitemap and nav entry in one table.
5. **B5.** Name the hand-synced pairs:
   - `homeColumns` and `scanHome` as one list of `{column, target}`;
   - `build.sql` inserts with named columns (`INSERT INTO t (a, b) SELECT …`).
6. **B6.** `store.LoadRaw` (86 lines): extract `headerIndex` and `loadPage`. It has no direct test, and the error wrapping is mixed (some errors carry the path, some don't), so keep that mix exactly or add a test first.
7. **B7.** `tools/tune`'s appeal SQL and `cli/backtest.go`'s are separate copies "kept in sync" by a comment. Share one only if the tuning runs are re-validated.

## Notes on the run

- **Commands this session couldn't run unattended:** `rm`, `git clean`, output redirection and `perl -i`. The edits were made with the editor tools instead.
- **The throwaway equivalence test** for #10's proof (old vs new window functions) was never committed. After the rebase onto the merged #6 it was rerun on #10 (119,720 cases equal) and then discarded.
- **Stalls:** `go` stalled once for over 30 minutes in a gate run (as the audit also saw). The same gate passed in 56 s when rerun. After the merge from `main`, one gate run had every `internal/e2e` subprocess time out at 60 s at once, even `assessgap` with no arguments. The same test passed in 2.4 s right after, and the full gate passed. It looked like the machine stalling on a freshly built binary, not a test bug, but it's worth watching in CI.
- **The run hit a usage limit before it finished.** A second session committed the last architecture-page edits (each on the layer that creates the files it names), merged `main` into #6, rebased the stack, recounted the sizes and ran `live-eval`.
- **`gh` stalls:** `gh` hung for a few minutes once (even `--help`), then recovered. `gh stack init` waits for a terminal, so run it with stdin closed.
