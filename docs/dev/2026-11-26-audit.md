# 2026-11-26: code audit after the MVP sprint

An unattended run audited the code on `main` at `3e2e2f1` (after PR #4) along eight dimensions: dead code, structure, correctness, security and privacy, tests, performance, ops, and docs. One reviewer per dimension, then an adversarial verifier re-read each finding on `origin/main` and tried to refute it. Findings that didn't hold up are dropped, and severities are the verifier's. Fixes are small themed branches. Large refactors are proposals only.

**No golden changed on any branch.** Two branches change what a homeowner can see in rare cases; both are explained under their findings (F2, F3).

## Performance

Measured read-only with `sqlite3` on the full database, using the server's own pragmas. The sandbox refused to run the built binary and `/usr/bin/time`, so there are no end-to-end `check` or `serve` timings and no RSS figures. That is worth doing on the server.

| What | Plan | Cost |
|---|---|---|
| Comp pool, largest neighborhood (72380, 12,457 homes) | `SEARCH assessment_year (year, nbhd, class)`, then primary keys | 61 ms, 3,125 pages (≈14 MB of cache) |
| Subject, latest year, neighborhood stats, PIN search | primary key | <1 ms |
| Address search | `SEARCH parcel_address` range, no temp B-tree | <0.1 ms per probe, at most 5 (15 after F4, on a miss) |
| Sales | `SEARCH sale_pin` plus a temp B-tree for a few rows | negligible |
| Startup township scan | `SCAN parcel` plus a temp B-tree | 1.16–1.30 s warm, 61,494 pages; left 210 MB in a connection's cache before F5 |

- **Database:** 2,456,972 pages of 4 KB, about 10 GB. The tables the server reads take about 1.9 GB.
- **Requests:** nothing loads a whole table per request. Go heap is about 5–15 MB per report, so 4 concurrent reports come to about 60 MB.
- **Tests:** the slowest is `TestRenderEveryHome` (2,101 PDFs, about 15 s); comps 2.3 s; golden 2.7 s; the whole gate about 50 s on an idle machine.
